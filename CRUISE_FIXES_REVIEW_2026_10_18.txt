I37 — Passed waypoint restrictions must not become CRZ speed targets
------------------------------------------------------------------
Reference owner: B738_restrict_data, original 149880 onward.
The output speed/id/index/target tuple resets on each call (149915 onward).
The first cruise scan already requires the endpoint to be at/after offset;
the missed-approach scan also starts at offset. The secondary reverse scan
(150257 onward) only checked the T/C/SID boundary, allowing a passed endpoint
to satisfy decel_before_idx < offset and be republished as a live restriction.

Invariant: a selected restriction endpoint is at/after the current active leg.
The deceleration lead may legitimately be behind it. The new guard therefore
checks endpoint >= offset, not decel_before_idx >= offset. It retains the
existing phase 2-4, T/C/SID boundary, cruise speed and distance gates.
The reverse search continues after excluding a passed candidate.

Lifecycle/consumer boundary: retain the shared restriction table and historical
route data; do not clear/re-key any cache, alter offset, change route geometry
or introduce another publisher. The existing producer recalculates admission
from the current offset and publishes the same output tuple to existing FMC
and plugin consumers. Direct/route edits/reset still use their existing data
rebuild and publication paths; there is no permanent waypoint blacklist.
The CLB, DES and missed-approach selection code is not rewritten.

Port reference: commit ed31443b;
Documentation/investigations/egpe_ensb_speed210_2026_10_06/RESULT.md and
INDEPENDENT_REVIEW.md. Those historical port checks do not validate this Lua.

I39 — W/STEP fuel uses one mass unit and the correct sign
------------------------------------------------------
Original calc_step_point sets sc_fuel_delta = sc_crz_fuel - crz_fuel (162735).
Positive delta therefore means additional burn. Both are calculated from the
same fuel-flow mass basis. Route fuel starts from simDR_fuel_weight or entered
fuel converted to kg (159635 onward); legs_data[n][40] stores kg (160862),
including the destination copy (161157/161160). KGS_LBS is defined at 533.

Only the W/STEP arm in B738_fmc_cruise (120339 onward) changes:
arrival fuel kg = existing predicted arrival fuel kg - sc_fuel_delta kg.
Divide by 1000 and, for LBS, convert the complete difference with KGS_LBS.
This fixes both the extra-burn sign and the previously unconverted LBS delta.
Example: 10,000 kg base and 2,000 kg extra burn display 8.0 or 17.6 respectively.
Zero and negative deltas use the same expression; savings increase arrival fuel.
Existing step availability/validity gates, destination selection, ordinary
non-step fuel, sc_sav_pen and the step planner/cost model remain unchanged.
No output dataref, cache or shared fuel value is mutated by this display fix.
Port reference: commit 8d1b62945; only its arrival-fuel correction is adopted.
